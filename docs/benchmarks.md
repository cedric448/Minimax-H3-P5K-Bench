## 2. 方法论

- **输入(固定)**:结构化三段式 prompt(芭蕾女孩双镜头,含 00:04.800 镜头切换,见 `assets/ballet_t2va.txt`);seed=1101;steps=50;flow_shift 12/3;ratio=16:9(t2va)
- **时长**:10s(覆盖双镜头;官方参考数字为 5s 口径,对比时按 元/视频秒 归一化)
- **矩阵**:每方案 × 4 分辨率档(0.3/0.5/0.7MP/768P),每档 warmup×1(不计)+ 正式×3 取均值
- **指标**:
  - E2E 延迟:POST 提交 → MP4 下载完成;分解为 submit / queue / gen / download
  - 峰值显存/卡、功耗(nvidia-smi 1s 采样)
  - 稳态吞吐 T(视频秒/小时):latency 模式按单请求折算,throughput 模式并发连续提交测真实吞吐
  - 质量:INT8 vs BF16 同 prompt+seed 对比(人工盲评 + 抽帧);768P 与官方 API 直出参考片对比
- **fl2va 用例**:首帧图(`assets/de930b24-b17b-4973-9c14-d62a1f9618c7.jpg`,492×492)每方案 768P×1 验证链路
- **成本**:月成本 20000 元(8 卡 × 2500 元/卡/月,720h);**元/视频秒 = 20000 / (T × 720)**;对标官方 768P $0.08/s ≈ ¥0.57/s,盈亏平衡 T ≈ 49 视频秒/小时

## 3. 官方参考数据(768P / 5s / 50 步,预期管理用)

- 峰值显存:4×H200 U4 94.3GB/卡(OOM 警示);TP2+U2 63.5-66.0GB/卡;TP4+U1 49.8GB/卡;FSDP+U4 57.0GB/卡;2×RTX5090(Blackwell)TP2+offload 26.3GB/卡;1×RTX4090 kitchen_int8+offload ~18GB;8×B300 FP8 51.9GB/卡
- 延迟:4×H100 TP2+U2 13.25s/5s 片;FastH3 4×B300 4.1s(RTF 0.79)
